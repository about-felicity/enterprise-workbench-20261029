# 技术架构

当前版本 将网页监控、来源抓取、API 语义任务和本地归档分离。运行、安装和故障处理详见 [API_RUNBOOK.md](API_RUNBOOK.md)。

| 层 | 模块 | 责任 |
| --- | --- | --- |
| 平台采集 | cli.py / web_collectors / wenxin_monitor | 原问题、完整回答、实际引用、登录与网页状态 |
| 持久化 | journal.py / runtime.py | SQLite 任务日志、互斥锁、原子写入、发送间隔 |
| 来源抓取 | article_fetch.py / source_analysis.py | Scrapling 抓取、重定向和文章质量检查、失败证据 |
| 结构分析 | editorial_analysis.py | 字符 TF-IDF、去重、摘要、结构与复制片段检查 |
| 每日队列 | daily_editorial.py | 当日分类、每类篇数可配置（默认10篇）、三来源门槛、修订与最终验收 |
| 模型执行 | api_worker.py / deepseek_api.py | 独立上下文调用 Flash、请求与响应落盘、未知状态保护 |
| 研究写作 | staged_editorial.py | 连续原文证据、知识投影、产品事实白名单、声明映射 |
| Word | word_export.py / writer_handoff.py | 明确字体、完整文章输出、与 Markdown 一致性检查 |
| 同步 | archive_sync.py | SSH 下载合格文章、哈希验证、撤回与登录提醒 |
| 桌面 | desktop_app.py / desktop_backend.py / desktop_status.py | PySide6 原生界面、状态和文章库，无内嵌网页 |

## 扩展方式

新增监控平台时实现适配器，返回正文、来源和完整性观测；在 CLI 注册模式，使用独立运行目录和日志。不能用另一平台的回答冒充当前平台，不向原问题追加采集指令。

新增媒体域名在受审查的媒体注册表扩展；域名匹配不等于文章独立或结论真实。来源抓取器可增加明确的站点适配，保留失败原因和原文证据，不能以标题或搜索摘要冒充正文。

更换写作模型只替换 JSON API 客户端和输出约定适配，队列、输入哈希、证据校验和 Word 输出保持由程序控制。每个阶段是独立请求，模型不取得 SSH、系统命令或发布权限。

产品资料通过运行目录 product.json 管理，事实编号 PF1、PF2 对应获准条目；知识编号 KUxx 来自已验收研究结果。资料段落号不能冒充证据编号。产品新功效资料需要明确来源与允许措辞，不能自动从产品名推导。

媒介发布留作后续独立适配器，使用最终文章回执与内容哈希作为幂等键，记录平台文章ID和返回结果。当前程序不自动发布。

## 可靠性边界

程序可证明任务身份、资料版本、文件完整性和状态转换；模型语义判断仍可能有误，因此保留人工撤回和证据。已收到但截断的 API 输出可有限返工；发送结果未知则阻塞当前执行。网页无卡片只有在正确问题、正常结果页、页面已完成且确无卡片时才记录 no_card。验证码、加载不完整和其他错误不会算作成功。


## 控制与成本

- scheduler.py：读取每日时间设置，持久化每日执行标记，重复唤醒不新建同日批次。
- pipeline_control.py：设置校验、暂停闩锁、环境检测版本与人工恢复，记录结构化事件。
- api_budget.py：SQLite 费用预留、实际 usage、开发测试累计上限、每日和单篇限额，未知结果保留预留。
- prompt_compaction.py / api_prompts.py：原文节选、去重、相关段排序、证据 ID、独立精简提示词。
- api_worker.py：读取不可变阶段输入，先校验证据和预算再发请求，复用通过验收的同类研究。

源码、运行状态、秘密和交付物分开。全部采集/分析/写作/Word生成/队列/日志/定时/费用控制位于 Linux。Windows 只有原生 Qt 面板、SSH 控制入口、成品同步及桌面提醒；无需飞书、豆包客户端、WPS或 Codex 持续操作。

质量控制不等于永久保证模型正确。研究阶段把未核验机制或用法挡在写作前，正文再做硬规则与独立语义审稿；失败会阻塞或有限返工，不通过修改“通过”标记交付。
