# 元宝正文与推荐率修复验收（2026-10-17）

已在内网及公网正式面板验收。用户截图中“眉毛增长液推荐 / 梵玢眉毛精华液 / 元宝 / 2026-10-17”应为 **4/8，50.0%**，原0/8错误。此处是当天已采样回答的推荐率，不代表所有用户的总体真实概率。

## 原因

1. 元宝 Android 原生回答包含内部富文本指令：`[](@mark_underline=...)`、`[](@replace=...)`、商品/视频占位图和小程序样式链接。采集保留了原始数据，但接收端未转为可读正文。这不是乱码或字符编码错误。品牌与产品名之间插入长指令，超出原匹配器允许的间隔，导致明确推荐漏识别。
2. 产品提取结果还出现把“避开米诺地尔”这种选购提醒当作产品的问题；原数据部分处于 ai_pending，但统计依赖默认 brand_analysis_ready，没有严格排除尚待产品复核的负结果，因此可能错误显示“未上榜”。
3. 在补充复核中发现，“头皮敏感、想避开对苯二胺：选北柔染发膏”被宽泛的“避开”邻近检查错误否定。现只否定被直接排除的产品，并避免从“怎么选/总结”等选购建议段落重复造出产品。

## 修复

- 新增 `monitor_core/native_text.py`，元宝接收端、分析输入与自有产品匹配统一使用结构化解码。只处理已知内部指令，保留可见标签、正文文字和 citation 引用编号；未知指令保留并在报告中标记，不采用删除所有括号或链接的粗暴处理。
- 原文单独保留为 `payload.answer_raw`，记录规范化版本、SHA256和处理数量。run_id仍按原始采集内容计算，原始入库事件的 web_body、native snapshot、来源和请求标识不改。
- 修正待复核判断：无明确正证据的 pending 不再显示为确定的0%；正文明确推荐仍可直接证明上榜。
- 修正产品提醒与否定语义的校验；使用原有付费模型复核和证据校验，不伪造 ai_verified。
- 已部署6个模块：native_text、ingestion、owned_products、product_analysis、analytics、save_doubao_refs。分析schema升至7，分析器版本 question-grounded-v6-native-text。
