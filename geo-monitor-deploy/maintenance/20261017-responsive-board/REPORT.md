# 产品看板小屏自适应（2026-10-17）

已上线内网3000与公网 `/geo_monitor/`。

原月度汇总和每日明细表通过内联minWidth及固定列宽强制撑宽，侧栏进一步挤占可用空间，小屏必须横向拖动。现按看板容器实际宽度切换布局：宽屏保留表格；可用宽度不足时，每个产品成为带完整字段标签的卡片，模型自动排列/换行，文心与百度卡片保留并排显示。小屏继续换行，百分比、样本、日期、变化说明均保留，不缩放整页或隐藏模型列。保留正常纵向阅读滚动，24个产品不会强行压缩进单屏。

修改仅涉及 `dashboard-integration/app/Dashboard.tsx` 和 `globals.css`：增加单元格标签及模型列类别、CSS container queries、适当增加细节文字字号、长文本换行，解除看板宽屏内容区的旧1510px上限。测试还发现820px时下方绩效卡片的260px最小宽度撑出页面，一并改为可收缩网格。

正式构建成功。预览、正式内网、正式公网分别使用真实Chrome验证11个尺寸：2560×1440、1920×1080、1536×864、1440×900、1366×768、1280×720、1024×768、820×1180、768×1024、390×844、320×740。两区24行均保留，无页面横向溢出、无单元格或模型内容裁切，四模型与文心/百度两卡片齐全，调整窗口前后DOM数据一致。另验证元宝+眉毛问题筛选仍为4/8、50%。无JS错误，无生产测试POST。证据qa-preview.json、qa-production.json、qa-public.json及对应截图在服务器同维护目录。

预览最初因Chrome本地网络访问权限/CORS未加载API，没有记为通过；改为正常3000 origin加载候选UI、授权测试浏览器local-network-access后进行正式尺寸测试。首个尺寸测试发现820px绩效网格溢出，修复并重新构建后全部通过。
