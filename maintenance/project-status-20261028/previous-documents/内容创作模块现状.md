# 内容创作模块现状与执行逻辑

更新：2026年10月23日，北京时间。服务与预算只读核对时间16:16。生产、候选、真实输出和本次会话草稿分开记录。

**一 业务目标与两条资料流**

用户的主流程是：拿到链接，读懂原文，结合自己的产品知识库仿写，按体裁归档，输出完整Word。自动采集、调度、审稿、预算和恢复都为这个目标服务。

原文提供主题、展开方式、章节功能和竞品资料；产品知识库提供自有产品名称、成分、规格、检测与功效摘要、价格等信息。原文第一品牌的事实不能随“第一名”位置转给自有产品。

自有产品排第一，指产品列表中的第一项，不要求导语先宣布品牌和名次。读者困扰、选购问题、比较标准、产品介绍、横向归纳、结尾，是可参考的阅读顺序；实际结构随原文和任务变化。

分类发生在写作前，用来决定原文池和写法；完成后沿用类别归档。主题、人群是附属标签，不能代替排行、科普、测评这些体裁。

现有常规素材准备路径至少需要三篇完整媒体正文，才开始日任务。这是当前批量采集工作流的约束，不是用户“单链接仿写”的天然必要条件。直接链接入口与批量入口需要区分，不能把批量前提误当所有任务的要求。

**三 三个Agent与调度**

Structure Analyzer分析原文组织；Article Writer据当前产品资料写新文章；Article Reviewer独立审事实与全文逻辑。这是三种职责，不是固定三次API调用。

实际队列有taxonomy、research、writer、review阶段。新体裁分类通常本地执行；研究可能收费；writer内部还可能包括结构请求及多个章节请求；review包含事实、逻辑和必要仲裁。因此必须逐请求核算预算，不能由Agent数量推算费用。

studio负责计划和当日任务；worker串行执行；api_worker负责领取、发送、持久化与恢复；daily_editorial推进阶段和验收。服务active只表示进程运行，不表示文章已完成。

任务开始后使用当日资料快照，后来修改知识库不能静默覆盖旧稿依据。请求状态未知时保留现场和预留，不盲目重发。有效旧答复只能在输入指纹一致时恢复。

**四 产品数据在什么地方丢失**

实际链路是：原始Word → 保存的产品版本 → 当日product.json → reader_facts筛选 → PF证据 → CL声明 → 本节claim_ids → Writer正文。中间层省略的数据不会因为原Word还在，就自动进入正文。

导入模块保留完整文字，会将百分比、实测等主张标出来供确认。approved表示用户确认提供，和系统独立核验是两个概念。reader_facts会排除元数据提示、未独立核验的部分资质编号；有条件的品牌检测摘要可通过supplier_report_summary保留。

这一摘要通道要求id、method、conditions、result、limitation、source_quote六项，并核对导入原句。因此“Word里有数值”和“当前Writer获得可用的检测摘要”不是同一步。

排行01真实Writer实际使用的product.json，已经把不少功效、报告数据合并成“不作为已证实效果”的提示；后续过滤又排除了这些提示。Writer实际主要拿到成分、200ml规格及少量属性。这不表示用户Word没有数据，也不能据此认定资料为假。

原始小绿瓶Word确有pH 5.9、40℃泡沫高度140mm、有效物含量16.0%、4周脱发计数下降43.96%、12周下降33.96%、检测编号和参考价格。品牌数据应保留项目、周期、必要条件与原始归属，不能一概删除，也不能改写成作者亲测或给每位用户的效果承诺。

真实资料中另有周期冲突：发缝宽度减少27.53%、全头发量增加14200根，P16对应2周、P76对应12周，不能自行选一个。当前v2草稿未使用这组数据，记录在product_data_sources.json。

**五 为什么有结构和声明，文章仍可能不顺**

结构回答原文各节做什么；身份绑定回答本节写谁；声明账本回答事实来自哪里。它们不能代替新文章的主旨和论证设计：读者的问题是什么、本文能回答到哪里、每节新增什么、为什么进入下一节。

现有argument_plan有字段可用性矩阵，但不等于统一比较结论；Compiler很多reasoning仍是通用describe/scoped_explanation。实际分节请求没有完整的明确主旨、比较矩阵和逐节推理结果。

真实断点包括：范围从实测降为资料介绍，goal仍沿用原实测榜标题；导语获得35条全局声明，却缺导语独有任务；S1、S12、S13、S14共用一般建议CL0007；重试反馈处理标签和长度，没有纠正标题承诺与正文定位。因此容易反复写限制、核对方法或空泛建议。

V4的15区域、84锚点表示原文覆盖，不等于新文必须机械复刻15个对外小标题。此前隔离Writer适配器执行INTRO＋15区域＋END，是当时明确指定的样本执行方式，应与长期业务规则区分。

产品第一推荐位应出现在铺垫和标准之后；数据应服务于具体判断，如人体脱发计数、理化泡沫和价格分别回答不同问题，不能混成一个分数。一般字数、标签和风格不应抢在完整草稿交付前反复阻断；明确身份错误、事实错误和前后矛盾仍须处理。

**六 审稿、返修、Word与下载的关系**

事实审核要验证句子含义与原始材料相符，CL存在不能证明断言正确。全文审核要检查标题、问题、前提、推理、结论与承接。仲裁区分确定错误、有依据问题、待核对、一般建议和风格偏好。

返修意见必须绑定当前正文、来源与合同版本。局部事实问题可以补丁；全篇目标或比较依据失效不能只换一句话。任务修订配置和最多两轮内容修订共同约束执行；分节技术尝试不是内容修订次数。耗尽或审核不可用不能转为通过。

当前Word在Writer产出正文后生成，而正式下载主要读取approved，并检查收据、文件哈希及质量状态。因此“返回文字”“Word已保存”“前端可下载”“质量合格”是四个不同状态。用户当前要求先看完整草稿，这与正式成稿入口需要区分；本轮未修改下载业务代码。
