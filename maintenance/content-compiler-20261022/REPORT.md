# 结论账本与宽松继续写作策略

2026-10-22，本报告覆盖上一轮`content-unattended-20261022`之后的改造。用户随后明确要求“不要这么严”，**最终策略已按这一要求调整，不沿用附件方案中的全部硬拦截。**

## 最终运行行为

- 编译并保存`evidence_matrix.json`、`topic_feasibility.json`、`claim_ledger.json`、`reasoning_outline.json`、`compilation.json`。Evidence、Claim、Section、Issue、Repair共用结构定义与运行时校验，导出定义见`schemas.json`。
- 可写内容直接进入`READY`；缺少统一效果测试、没有真实实测记录、部分产品资料缺项时进入`READY_WITH_LIMITS`，**整篇继续**。范围调整为资料介绍/比较，缺失的具体属性省略。不会自动编造测试、效果或优劣结论。
- 同一产品规格冲突时，从可写账本中省略冲突记录，保留其他可用事实；原记录另存，没有静默改写成某个数值。没有任何可用材料才停止写作。
- Writer使用已分配的CL声明，每节绑定产品与声明范围。一般选择意见可以自然展开。来源映射、章节知识ID和合同哈希由程序生成，减少重复抄写带来的格式退稿。
- 新写作路径不再同时发送旧`draft_markdown`和新`document`两套格式，也不把一组旧限制再逐条叠到同一个正文提示中。完整合同在本地保存，传给模型的视图只保留一份事实正文和必要的身份、状态、条件。
- 审稿使用同一份声明账本，仍检查文字是否忠实于事实，不能凭CL编号存在就通过。材料中的指令只作为数据处理。NO_INSERT时不会把自有产品事实释放为可写声明。
- 重复资料边界说明转为润色提醒，**不再仅因免责声明较多而拒绝整篇**。正文内部矛盾、无依据的具体事实与缺失主体章节仍需处理。
- 返修路由校验正文版本、定位与问题来源。段内问题采用段落补丁，跨章节冲突扩大到相关章节，整体排名依据失效转重规划。无法定位的审稿结论保留争议，不盲目整篇重写，也不伪装成审稿已通过。
- 编译版文章最多两轮内容修订，之后保留失败状态。任务界面能够显示资料不足、需重规划、审稿待核对和修订耗尽等原因，结束失败的任务不会继续显示“正在创作”。

## 尚未打通的部分

这一版结论账本主要约束已有资料的允许复述范围，尚未完成复杂比较推理的自动规划与验证。章节已经有声明范围，但正文仍是一次长文请求，**没有实现逐节独立生成**。排行空主体的真实失败说明该环节仍需改进。

审稿意见已能绑定位置、区分返修范围和保留争议，尚未实现可靠的独立语义仲裁器；不能说“普通建议误判”已全部解决。重新检索补资料、自动重建大纲、不同粒度修订后的稳定收敛，也尚未完整实测。

后续应先修复章节生成的完整性，并用C34/C60与11款/十款等真实错误校准审稿和返修，再做两篇完整通过及跨日无人介入验收。原额度继续限制后续付费步骤；本轮没有提高预算，也没有为了通过而取消事实和逻辑复审。

**当前结论：宽松继续策略、结论账本和返修路由已上线；内容质量闭环和无人值守仍未完成。**
