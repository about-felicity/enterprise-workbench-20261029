## 工作流

Word知识库导入并确认 → 配置独立问题、通道、时间、频率、预算和分类篇数 → 保存任务 → 独立采集与媒体全文准备 → 分析、写作、独立审稿 → Word、Markdown和溯源下载。创作素材默认独立于主GEO，显式选择时可只读复用已有完整素材。

主GEO北京时间09:00；创作通常01:00采集、最早04:00写作，具体计划及一次性执行日期优先。百度完成后运行文心。DeepSeek主监测现采用手动Chrome插件公网回传，不能根据历史浏览器实现自动恢复已停用服务或旧测试。

任务与当日资料保留版本快照；同一任务日幂等建job，跨日接续原日期。用户暂停阻止后续新任务，已发送请求安全收尾。未知API发送保留现场与费用预留，不自动重放。费用使用原共享账本，按计划预算与共享日限额共同约束，不清账、不提高预算来凑完成。

## 成稿和下载

分类篇数和产品详解按任务配置，不写死品牌或目标篇数。支持排行、科普及显式配置的测评类；测评先定义统一维度，再基于资料逐款比较，缺数据不补造亲测或评分。旧任务保留原分类快照。资料不足、主话题与产品形态不匹配的原文在付款前拦截；某类素材不足保留缺口，不用另一类凑数。事实审稿通过后另行进行article-logic-v2全文逻辑审稿，逐段核对前提、推理、结论以及开头、结尾和产品例子的关系，并按真实顺序逐一说明全部小标题的作用和承接，不能漏节、倒序或依赖后文才有的前提。可以先提出结论再展开依据，不机械要求固定作文结构。审核证书绑定实际稿件和产品，修改后必须重新审核；标题不能掩盖正文产品错位。知识库导入不等于独立核实功效或检测报告。

导出结构为`任务名_日期/文章种类/具体文章及信息/`，包含原始Word、原文链接、媒体信息、执行日志、审核与事实映射。缺失作者/时间/官号身份明确标注。旧稿不合格时保留原件并停止下载，修订重审通过后恢复。

服务端检查ZIP与CRC，前端拦截登录HTML、JSON错误和截断文件；空筛选返回明确错误，不再生成零篇空包。历史坏文件仍需与其下载时间及真实文件逐一对应，不能仅凭新包正常就归因。
